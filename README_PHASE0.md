# PSMC compatibility project — Phase 0

This folder contains a pinned vanilla PSMC reference, source audit, synthetic differential tests, bootstrap manifests, and profiling/benchmark evidence. It does **not** contain a Rust inference engine or a demonstrated acceleration.

Start with [the Phase 0 decision](docs/phase-0-decision.md). The current recommendation is to retain vanilla PSMC as the strict oracle and consider equivalent legacy acceleration after resolving reference failures and reviewing a numerical contract. The real workload is `not_run`; its bootstraps already run in parallel.

## Deliverables

- [Reference contract](docs/reference-contract.md): actual flags, encoding, boundaries, full counts, objective, optimizer and bootstrap behavior.
- [Workload manifest](bench/workload.json): generated input hashes, ordered blocks, 30 exact materialized replicates, missing real-workload information.
- [Baseline](bench/baseline.json): **five-iteration partial-trajectory smoke only**. The separate [30-iteration reference failures](bench/failed-23state.json) remain unresolved.
- [Differential tests](bench/differential.json): 52 passing mechanics/parity checks, with nonfinite reference outputs classified separately.
- [Profiles](bench/profile.json): vanilla timing, gprof sampling, and separately instrumented phase measurements.
- [PHLASH audit](docs/phlash-audit.md): CPU/custom-GPU feasibility, method differences, and a reproduced input-coverage issue.

The supplied `AGENTS.md`, execution plan, startup note, and algebra result were copied for project context. Four referenced documents were missing. `EXECPLAN.md` records the new evidence without treating the supplied design's historical completion claims as fresh verification.

## Reproduce the C harness

Run these commands from this directory in a fresh extracted copy. Required tools are Python 3.12+, Git, GCC, make, Perl, GNU time, and gprof. The C executable dynamically links libm and libz. No CUDA toolkit, Rust packages, or Python numerical packages are needed for the C harness.

On this Ubuntu 24.04 machine, the zlib runtime existed but development headers did not. They were downloaded and extracted locally; no system packages were installed:

```bash
mkdir -p work/deps/zlib
cd work/deps
apt-get download zlib1g-dev=1:1.3.dfsg-3.1ubuntu2.2
dpkg-deb -x zlib1g-dev_*.deb zlib
cd ../..
python3 reference/build.py --zlib-include work/deps/zlib/usr/include
python3 reference/build.py --zlib-include work/deps/zlib/usr/include --instrumented
python3 reference/build.py --zlib-include work/deps/zlib/usr/include --gprof
python3 bench/prepare.py
python3 bench/differential.py
python3 bench/run.py
python3 bench/profile.py
```

Builds use the fixed commit `82fa2ada83ee463fe1251b562ae3d60e82d7ad6a`, even when the repository's branch later moves. An existing clone can be supplied with `--source PATH`. On a machine with zlib headers installed, omit `--zlib-include`. Build scripts refuse to overwrite an existing build directory. Reports and raw test/benchmark outputs are regenerated by the benchmark scripts; preserve a previous evidence bundle before rerunning.

Run benchmarks and profiling sequentially, with no other test job running. Existing user processes are outside this harness's control. The measured worker counts (1, 2, 4) are a bounded diagnostic sweep, not an optimal production scheduling recommendation.

The five-iteration smoke does not repair or supersede the full-trajectory failure. Reproduce each affected 30-iteration case directly, substituting `16`, `26`, or `28`:

```bash
work/vanilla/psmc -p '4+5*3+4' -N 30 -t 15 -r 4 -I 0 tests/fixtures/bootstrap/replicate-16.psmcfa
```

The test-only instrumented executable supports environment variables documented in [instrumentation.md](reference/instrumentation.md). It must not replace vanilla for throughput measurements. Its seed control allows the original bootstrap procedure to be replayed; original `-S` means **simulate**, not seed.

PHLASH uses a separate isolated Python environment. Its exact source/dependencies, hybrid CPU-JAX/custom-CUDA settings, commands, and remaining validation requirements are in its audit. That environment is not included in the portable bundle.

## Evidence and boundaries

`bench/raw/` retains successful, failed, interrupted, and superseded measurement evidence. Successful parity of NaN output is not scientific validation. Only the expected `RI inf` at round zero is exempted from the finite-output check. The matrix-path enumeration tolerance is a fixed test diagnostic, not an approved tolerance for an accelerated PSMC implementation.

`work/` contains rebuildable local source/build files and is excluded from the portable archive. No user genomes were accessed or uploaded. The upstream license is preserved in [LICENSE.psmc.txt](reference/LICENSE.psmc.txt); fetched source retains its notices.

Before Phase 1: review the decision, recover or replace the four missing design/validation documents, record the real command/input/splitting/worker budget, investigate reference nonfinite cases, and agree on strict/equivalent support boundaries. No numerical optimization or GPU legacy backend has been implemented.
